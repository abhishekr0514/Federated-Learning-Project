## 2. Frontend architecture

### 2.1 Framework and routing

- **No React Router:** Authentication gates the entire app. After login, **one dashboard component** is chosen by canonical role (`App.jsx` lines 10–36).
- **Roles → dashboards:** `SUPER_ADMIN` → `SuperAdminDashboard`; `HOSPITAL_ADMIN` → `HospitalAdminDashboard`; `CLINICIAN` → `ClinicianDashboard`; `PATIENT` → `PatientDashboard`.
- **Tab navigation:** Sidebars (`Sidebar.jsx`, layouts) use `activeTab` state inside each dashboard—not URL paths.

**Verification:** VERIFIED IN CODE (`frontend/src/App.jsx`).

### 2.2 API client and auth state

- **HTTP client:** `frontend/src/services/api.js` — `apiRequest()` with JWT in `sessionStorage` (`medshield_access_token`), refresh via `/api/v1/auth/refresh`.
- **Auth context:** `frontend/src/context/AuthContext.jsx` loads `/api/v1/auth/me`, derives roles and inferred permission strings for UI (not a substitute for server RBAC).

**Verification:** VERIFIED IN CODE.

### 2.3 Role-based navigation

- Patient nav: My Health, Records, Reports, Assessment, Results, Questions (`Sidebar.jsx` ~156–179).
- Clinician nav: Workspace, Diagnostic Studio, Patients, Documents, Questions, Federated Node, GAT Diagnosis, Causal AI (`Sidebar.jsx` ~133–154).

```mermaid

  end
  subgraph Flower
    SL[SuperLink / SuperNodes]
    FLAPP[medshield_fl_app FedAvg]
  end
  PD --> PAT
  CD --> CLN
  DW --> ECG
  DW --> GAT
  ECG --> ENC
  GAT --> GRT
  GAT --> DP
  ECG --> DP
  PAT --> DP
  PAT --> DOC
  PAT --> Q
  CLN --> Q
  FED --> SL
  SL --> FLAPP
```

**Live clinician inference path (GAT):**

1. `POST /api/v1/ecg-report/embed` — raw ECG waveform + report text → 128-d ECG embedding + 128-d text embedding (`DiagnosticWorkspace.jsx` `handleSubmitGatFusionPrediction`).
2. `POST /api/v1/gat-fusion/evaluate?patient_id=...` — GAT head → logits → softmax → argmax class + max softmax as confidence (`ml/inference/fusion_runtime.py` lines 160–173).
3. Optional persistence → `diagnosis_predictions` when `patient_id` authorized (`gat_fusion_service.py`).

**Flower path:**

- Super Admin UI → `POST /api/v1/federated/start` → `FlowerSupervisor` / SuperLink → `flwr run` with `medshield_fl_app.py`.
- Clients train **GAT head only** on **precomputed embeddings** in `federated_fl_bundle.pt`; FedAvg aggregates weight vectors; global checkpoint saved under `data/processed/federated/gat_ecg_report_runs/`.
- **Not sent over Flower:** raw ECG, raw clinical text, patient DB rows (VERIFIED IN CODE comments in `medshield_fl_app.py` lines 3–5).

## 9. Architecture limitations (honest)

1. **`GET /api/v1/metrics/evaluation` returns 501** — dashboard must use static `reports/model_evaluation/` files, not live API (`metrics.py` lines 9–18).
2. **Sidebar claim “Zero raw patient PII transmitted across hospital boundaries”** — marketing-style; actual FL demo uses **synthetic PTB-XL embeddings**, not live hospital feeds (UI ≠ production privacy proof).
3. **Single-page tabs** — no deep-linkable patient/clinician URLs.
4. **Evaluation train subset in bundle:** 1500 train embeddings reused from cache vs 12,898 eligible train records (`evaluation_manifest.json`) — research limitation, not full-data FL retrain.
